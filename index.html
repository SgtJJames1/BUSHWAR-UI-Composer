    WR WORKFLOWschema 3

    Composer → Workbench workflow

    1. Design at the root size you will set in Layout Editor (1920 × 1080 or your target). Anchors, not pixels, carry the layout to other resolutions.
    2. Export the Workbench import plan (schema 3). It carries widgets, anchors/bounds, controller source, and a layout scaffold request.
    3. Validate the plan in Workbench with the import-plan plugin (BUSHWAR-UIComposer-Validation). Schema 1/2 plans are rejected.
    4. Create the layout in Workbench Layout Editor from the scaffold request, or author the tree manually. Workbench owns .layout serialization and widget GUIDs — never hand-edit .layout XML.
    5. Register the layout; Workbench generates its .layout.meta GUID. Never copy metadata from another addon.
    6. Load the .meta into Handoff (or paste the GUID). The generated controller uses a GUID-qualified ResourceName; a bare path or {0000000000000000} resolves to null.
    7. Export the controller scaffold and copy controllerSource into your addon's controllerPath.
    8. Compile and smoke-test in-game. Verify the layout renders at your target resolutions (Layout Editor Live Preview) and that engine bindings read PlayerManager — the browser snapshot is preview evidence only.

    Fidelity contract: only native widgets (Frame, Text, Button, Image, ProgressBar, Scroll, layouts, EditBox, CheckBox) survive the handoff. Gradients, shadows, rounded corners, and web typography have no Reforger equivalent. Custom images must become registered textures in your mod. The UI Composer mod owns UI resources and named-child contracts; your mod owns authority, permissions, and replication.

    Mod prep checklist

    • Your target addon must depend on BUSHWAR-UIComposer-Core (B3A5F08C0D504D96) when the plan uses the Core row resource.
    • Place the generated controller at the plan's controllerPath (Scripts/Game/UI/…) and compile it in the target addon.
    • Register the target layout and every row layout; keep GUID-qualified ResourceNames in the controller.
    • Register any custom textures in your addon — the Composer ships no Reforger assets.
    • Your addon owns authority, permissions, and replication; the Composer mod owns UI resources and named-child contracts.

    Tutorials & workflows

    1. Pick a base scene.Use the Base scene cards on the left: Blank workspace for a clean canvas or Vanilla GM to trace the reference screenshot.
    2. Set the root size.Workbench documents a minimum 1920 × 1080. Change Width/Height in the Screen panel or use the 1080p / 1440p / 4K presets.
    3. Build the UI.Add elements from the Element library, then select layers on the canvas to edit their position, size, text, colors, and bindings in the Selection panel.
    4. Track readiness.The Handoff panel shows an eight-step workflow with a live count; Validate Workbench handoff lists anything blocking an export.
    5. Save early, save often.Save project writes a portable .bwui.json; autosave keeps a local recovery cache.
    1. Add and arrange layers.The Element library covers panels, text, buttons, icons, windows, dialogs, toasts, tables, inputs, toggles, and GM controls. Drag on the canvas to position; the Layers list reorders with ↑/↓.
    2. Edit the selected widget.Use the Selection panel: Name, X/Y/W/H, Text, Fill/Text/Border/Accent colors, Font px, Radius, Opacity, Visible, and Lock. Names prefixed m_w are the ones the generated controller looks up.
    3. Trace a reference.Add to reference board embeds locked reference layers that travel with the project; Use temporary screenshot is a quick tracing aid. Use the base scene opacity and reference opacity sliders.
    4. Preview and export images.Preview exercises assigned callbacks locally; Export PNG renders the canvas at full resolution.
    5. Prefer registered sources.Palette layers can adopt a registered WLib/vanilla layout source from the inspector so the Workbench handoff carries the real prefab instead of a generic mock.
    1. Validate.Click Validate Workbench handoff and fix every warning (canvas size, unlocked references, missing GUIDs, unsupported bindings).
    2. Export the schema-3 plan.Export Workbench import plan (or the handoff bundle) carries widgets, anchors, controller source, and a layout scaffold request.
    3. Validate in Workbench.Use the import-plan plugin in the BUSHWAR-UIComposer-Validation addon; schema 1/2 plans are rejected.
    4. Create the layout.Open Workbench Layout Editor and build the tree from the copied/downloaded scaffold request. Workbench owns .layout serialization — never hand-edit the XML.
    5. Register and copy the GUID.Registering generates the .layout.meta. Load it into Handoff (or paste the 16-character GUID) so the controller compiles with a GUID-qualified ResourceName.
    6. Export the controller.Export controller writes the EnforceScript scaffold; place it at the plan's controllerPath in your addon.
    7. Compile and smoke-test.Compile in Workbench, run Layout Editor Live Preview at your target resolutions, then verify the in-game layout renders and its bindings behave.
    1. Declare the Core dependency.When the plan uses the Core row resource, your target addon must depend on BUSHWAR-UIComposer-Core (B3A5F08C0D504D96). The Mod prep note in Handoff tells you when it is required.
    2. Place the controller.Copy controllerSource to Scripts/Game/UI/BWUIC_<Layout>Controller.c in your addon and compile it.
    3. Register every layout.The target layout and each row layout need fresh Workbench .meta GUIDs; keep every ResourceName GUID-qualified in the controller.
    4. Register custom textures.The Composer ships no Reforger assets — import and register any custom images in your addon before referencing them.
    5. Own your authority.The Composer mod provides UI resources and named-child contracts. Permissions, replication, and server RPCs belong to your addon; engine bindings re-query PlayerManager at runtime and never trust the browser snapshot.
    1. Capture a context snapshot.In-game, run the Export UI Context action (or the generated controller's export callback) to write $profile:BUSHWAR-UIComposer/runtime-context.json.
    2. Import it here.Import Workbench context reads the snapshot so the browser preview shows the real connected roster, count, and GM editor state.
    3. Treat it as preview only.The snapshot is timestamped evidence. Generated controllers always re-query PlayerManager.GetPlayerCount() / GetPlayers / GetPlayerName when the layout opens; empty names are omitted and invalid IDs are never rendered.
    4. Refresh live values.Assign Refresh live engine values to a button; the generated controller repaints count and rows in memory without writing player data to disk.
    1. Save / Open projects.Save project and Open project use portable .bwui.json bundles that embed reference images.
    2. Templates.Save current as template stores a local reusable design; Export current / Import template share bundles that keep embedded references.
    3. Workbench exports.Export the import plan, the complete handoff bundle, the controller scaffold, and the layout scaffold request from the Handoff panel.
    4. PNG.Export PNG renders the canvas for quick sharing or documentation.
